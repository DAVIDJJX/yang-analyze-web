# Yang-analyze web

環境監測 raw data → 環評申報報表 轉換工具（純靜態網頁，無後端、無資料上傳，
所有資料只存在使用者瀏覽器本機）。
第一階段：網頁骨架＋**水質模組**。

> **線上版**：https://davidjjx.github.io/yang-analyze-web/ （GitHub Pages）

## 使用方式

### 線上（任何電腦）
開啟上方網址即可。第一次會預載一組**示範案場／示範測站**（DEMO-001），
請至「案場管理」「測站管理」改成實際資料，或用「設定/備份 → 還原備份」
匯入你在其他電腦匯出的 JSON 備份檔。

### 本機
- 雙擊 `serve.bat`（自動開 `http://localhost:8788/`），或
- 直接用 Chrome / Edge 雙擊開啟 `index.html`

### 操作流程

1. 左側「資料轉換」（預設頁）→ 把檢驗室的「水質檢測報告」Excel 拖進上傳區
   （可多檔，.xls/.xlsx/.xlsm；每個工作表視為一個監測點）
2. 預覽表出現，**紅色儲存格＝缺漏**（「時間(迄)」raw data 一定沒有，需手動填；
   點紅色儲存格會**預填該測站上次填過的值**）
3. 補完後右下「匯出 Excel」→ 下載申報檔
   （含「監測點基本資料」＋「水質檢測項目」兩個工作表）

## 目錄結構

```
index.html            主程式入口
serve.bat             本機啟動器（Windows）
.nojekyll             GitHub Pages 設定（停用 Jekyll 處理）
css/main.css          全部樣式（邏輯與外觀嚴格分離）
lib/xlsx.full.min.js  SheetJS 0.20.3（本地載入、離線可用；讀值取公式快取結果）
js/core/              共用引擎（通用，不含水質專屬邏輯）
  reader.js             SheetJS 包裝
  parser.js             解析引擎（吃模組設定檔）＋共用工具
  validator.js          必填欄位驗證
  exporter.js           匯出引擎
  xlsxwriter.js         自製 .xlsx 產生器（含字型/格式/欄寬）
  storage.js            IndexedDB＋JSON 備份/還原
js/configs/water.js   水質設定檔（解析規則＋21 欄輸出規格）
js/db/water_db.js     對照表預設值＋示範種子資料
js/db/code_tables.js  官方代碼表全收錄（單位 1–161、檢測機構；規範查閱頁可搜尋）
templates/            官方空白範本五類（水質/空氣/噪音/地質/生態，接「下載空白範本」）
docs/                 官方代碼表 PDF＋模組開發規格（air/noise spec、水質辭典核對報告）
tests/                黃金樣本測試框架（通用、可公開；不含真實資料）
test_data/            測試資料（真實 raw data／成品／setup；.gitignore 排除，僅本機）
```

**之後加空氣、噪音**：只需新增 `js/configs/air.js`、`js/db/air_db.js` 等設定檔，
引擎（js/core/）不用動。

## 資料模型重點

- 每個欄位帶來源標記：`parsed`（解析取得）／`manual`（手動輸入；測站記憶帶入者另標 via:memory）
- **測站記憶**：座標（TWD97-TM2＝代碼3／WGS84＝代碼2）存 IndexedDB，同名或別名自動帶入；
  匯出成功時自動回寫（含「上次時間(迄)」與別名學習，例：○○測站放流口→○○測站）
- **案場管理**：計畫代碼等 8 欄填一次，匯出時自動生成「監測點基本資料」工作表
- 解析結果自動存「匯入紀錄」，可重開繼續編輯
- **資料只存在瀏覽器本機（IndexedDB），不會上傳到任何伺服器**；換電腦用「設定/備份」搬

## 水質解析規則（已通過逐格驗證）

| 規則 | 說明 |
|---|---|
| 每工作表＝一監測點 | F8=採樣地點、B11=樣品特性、A2=許可證號（第0xx號→數字） |
| 民國年 | J9~N9 民國年/月/日/時/分，+1911 轉西元 |
| 檢驗項目 | 第 15 列起 A/C/D/E/F 欄，遇空列或「備註」停止 |
| ND | 比較關係、檢測數值皆填 ND（檢測極限照列） |
| NA | 填「未檢測」 |
| `<x` | 比較關係 `<`＋數值 x |
| 大腸桿菌群 | `6.0×104` → 60000 |
| 偵測極限 `--` | 留空 |
| 檢測方法 | 去版次（NIEA W217.51A→NIEA W217）；溶氧預設覆寫 NIEA W422（「對照表編輯」可改） |
| 單位代碼 | ℃=4、mg/L=47、mg P/L=47、μmho/cm=143、m3/min=34、CFU/100mL=8、無單位=161 |
| 樣品特性→類別 | 河川水→河川、放流水→污廢水…（「對照表編輯」可擴充） |

## 改版後怎麼更新網站

在 `yang-analyze-web` 資料夾開終端機：

```
git add -A
git commit -m "說明這次改了什麼"
git push
```

推上去約 1 分鐘後，GitHub Pages 自動更新（瀏覽器可能要 Ctrl+F5 強制重新整理）。

## 換電腦時資料怎麼搬

1. 舊電腦（用你平常開啟工具的那個入口）：「設定/備份」→「匯出備份檔」→ 存下 JSON
2. 新電腦：開網站 →「設定/備份」→「還原備份…」→ 選那個 JSON → 完成
   （案場、測站座標、匯入紀錄、對照表修改全部一次搬過去）

> 注意：瀏覽器資料跟「網址來源」綁定──`file://`、`http://localhost:8788`、
> 線上網址三者是**各自獨立**的資料庫；要在哪裡用就往哪裡還原。

## 已知事項

1. 「時間(迄)」永遠要手動填（raw data 沒有）；介面會預填該測站上次的值。
2. 溶氧方法預設覆寫 W422（申報慣例）；要照報告原文時到「對照表編輯→檢測方法覆寫」刪掉溶氧那列。
3. 官方單位代碼表（1–161）與檢測機構代碼表已完整內建（「規範查閱」可搜尋、附 PDF 原檔）；
   解析用的「單位→代碼」對照遇新單位仍會出警告，至「對照表編輯」補一次即可。
4. 與官方水質辭典的核對結果（含 mg P/L 代碼 41 vs 47 等待確認事項）見
   `docs/water_dictionary_check.md`；空氣、噪音模組開發規格見 `docs/air_module_spec.md`、
   `docs/noise_module_spec.md`。
